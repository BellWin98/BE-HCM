# 지식 메모 제목 + 접힌 목록 설계

## 왜

지식 메모 목록을 스크롤하면서 "이게 그 메모였나" 하고 하나씩 펼쳐 보는 게 가장 답답하다.
지금 카드는 분류·내용 4줄·이미지·출처·태그·버튼을 전부 펼쳐 보여 한 화면에 몇 개 안 들어간다.

제목은 DB 조회 속도를 올리지 않는다(검색이 `LIKE '%어%'` 라 인덱스를 못 탄다). 목표는 **사람이 목록에서 알아보는 속도**다.

## 목표 / 비목표

- 목표: 메모에 선택 입력 제목을 붙이고, 목록을 2~3줄짜리 접힌 행으로 보여 한 화면에 훨씬 많이 들어오게 한다.
- 목표: 제목도 검색 대상에 포함한다.
- 비목표: 검색 결과 관련도 정렬(제목 일치 우선), 전문 검색 인덱스.
- 실패 조건: 제목이 필수가 되어 빠른 메모·공유하기 저장이 번거로워지는 것. 기존(제목 없는) 메모가 목록에서 알아보기 어려워지는 것.

## 접근 방식

| 안 | 내용 | 판단 |
|----|------|------|
| A | 제목만 추가, 카드 그대로 | 카드 높이가 그대로라 스크롤 문제 해결 안 됨 |
| **B** | **제목 추가 + 목록 접힘, 탭하면 펼침** | **선택.** 알아보기(제목)와 밀도(접힘)를 함께 해결 |
| C | DB 변경 없이 내용 첫 줄로 접힌 목록 | 기사 붙여넣기 메모는 첫 줄로 식별이 안 됨 |

## 설계

### 백엔드 (BE-HCM)

- `knowledge_note.title VARCHAR(100) NULL` — Flyway `V17__add_knowledge_note_title.sql`
  (DDL 한 개, `ALGORITHM = INPLACE, LOCK = NONE`). 기존 메모는 NULL 로 남는다(백필 없음).
- `KnowledgeNote` 에 `title`, `MAX_TITLE_LENGTH = 100`. 빌더·`update` 에 추가.
- `KnowledgeNoteRequest` / `KnowledgeNoteResponse` 에 `title`. 서비스에서 trim → 빈 값은 null, 길이 초과는 기존 필드와 같은 방식으로 400.
- "내용 또는 이미지 중 하나는 있어야 한다" 규칙은 그대로 둔다(제목만 있는 메모는 허용하지 않음).
- `KnowledgeNoteSpecs.matchesTerm` 의 OR 에 `title LIKE` 추가.

### 프론트엔드 (FE-HCM)

- 타입·API: `KnowledgeNote.title: string | null`, 입력에 `title?`.
- 작성 폼(`KnowledgeNoteFormDialog`, 빠른 메모도 같은 폼): 내용 위에 `제목 (선택)` 한 줄 입력, 100자 제한.
- 공유하기: 공유된 `title` 을 제목 칸에도 미리 채운다(`sourceText` 처리는 기존대로).
- `KnowledgeNoteCard` 기본은 접힘:
  ```
  [분류] [비공개] [종목]            나 · 2026-11-18
  HBM 증설 관련 메모          🖼2  #반도체 #메모리
  ```
  - 2번째 줄 표시 우선순위: 제목(굵게) → 내용 첫 줄(보통 굵기) → `이미지 메모`.
  - 한 줄로 자르고(`truncate`), 이미지 개수와 태그는 오른쪽에 작게.
  - 카드(배지·태그 버튼 제외)를 누르면 펼침/접힘. 펼치면 지금 카드 본문 전체(내용 전문·이미지·출처·태그·수정/삭제)를 보여준다. 펼친 상태에서는 내용 4줄 접기를 쓰지 않는다.
  - 펼침 상태는 카드별 로컬 state, 저장하지 않는다. 검색 중에도 기본은 접힘.
- `StockNotesPanel`: 제목이 있으면 내용 위에 굵게 한 줄 추가(구조는 유지).

## 빌더에게 맡기는 것

- 접힌 행의 정확한 간격·아이콘, 펼침 애니메이션 여부.
- 접힘/펼침 토글의 접근성 처리(`aria-expanded`, 키보드).
